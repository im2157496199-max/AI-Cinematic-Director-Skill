# COSTUME_DESIGN_CORE.md

> Lightweight costume layer. Visual richness is expected to come primarily from project references / setting-book case library.

## Pipeline
CHARACTER / STORY / WORLD -> COSTUME PURPOSE -> CONSTRAINTS -> SILHOUETTE / LAYERS -> MATERIAL / DRAPE -> COLOR / PATTERN / ACCESSORIES -> STYLE SHEET / MULTI-VIEW -> CONTINUITY LOCKS -> GENERATION

## Costume purpose
Record role/occupation, current activity, social/faction identity, location/world context, story state/milestone, and practical/ceremonial/expressive function.

## Readability priority
1. silhouette
2. large color/value masses
3. signature layer/accessory
4. medium construction detail
5. small ornament

Validate at intended output scale.

## Layer model
Track name, body region, over/under relation, attachment/closure, material family, stiffness/drape, movement behavior, and continuity-critical details.

## Style-sheet minimum
Use only views needed by the task: hero/full-body, back or 3/4 if hidden information matters, dominant camera/game view when relevant, plus material/accessory/palette/pattern/reference/motif callouts.

## Variant system
When multiple outfits exist, define shared world/faction language plus controlled variation.

## Costume continuity state
Track outfit_id, current layers, accessories, damage/dirt/wetness, open/closed/tucked/rolled states, removed/equipped items, transformation/story milestone. No unexplained outfit reset between panels/shots.

## Style ownership
This module does not decide whether the project looks like Persona, Elden Ring, JOJO, Blue Archive, historical realism, street fashion, or another style. That comes from current project references and case library.
